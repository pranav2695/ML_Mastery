## System design for Recommender system
For the app we want to recommend 4-5 items, here it will work as a funnel we will start with all the skus then in each step will reduce the skus to recommend
## Stage-1
- If we had 500k SKUs we will select the 400 skus using different channels, we want the SLAs to be less than 50ms we can apply any heavy deep learning algorithm, we will divide the work into to small strategies so that we can recommend the product in the real time. we will have 4 channels to select the work.  
### Channel-1 
- we will use the two tower approach, where we will have tower-1 and tower-2 for user tower and sku tower, we will create the vector of all the users using used id, demographics, spending tier, past click, items in cart etc. for sku vector we will have all the details, text description, pack size, price bucket. we will keep the skus vectors precomputed and then we will calculate the cosine simaliarity between the user tower and sku tower (there are other algorithms also)this calculation we will only do the users which are online on the app. and select the top 100 or something skus.
### Channel-2
- we will do the Market basket analysis using the association rule, calculate the lift, support and confidence and select the skus for here.
$$\text{Support}(A \rightarrow B) = P(A \cap B)$$
$$\text{Confidence}(A \rightarrow B) = \frac{P(A \cap B)}{P(A)}$$
$$\text{Lift}(A \rightarrow B) = \frac{P(A \cap B)}{P(A) \cdot P(B)}$$
### Channel-3
- we will also recommend the products which are staples, we will calculate the time elasped by last order and calculate kind of z value and if it will in certain range then we will recommend some of those products as well.
### Channel-4
- we will also recommend the skus which are seen in the last 15 mins in the same session.  
Now we will take the union of all the product and create the list of 400 skus.  
## Stage-2 (Heavy scoring and Multi tasking Ranking)
Now we will rank these skus using deep learning algorithm like multi gate mixture of experts model etc and rank each product. with the desc order of score. 
$$\text{Rank Score} = \left( P(\text{Click})^{w_1} \times P(\text{Cart} \mid \text{Click})^{w_2} \times P(\text{Purchase} \mid \text{Cart})^{w_3} \right) \times \text{Margin Multiplier} \times \text{Promo Boost}$$
## Stage-3 
Now we will do the reranking based on the business logic or we can apply guard rails like dont recommend the sku if inventory is less than 2 units or we will remove the same catergory if appering more than twice for eg we are recommending the 5 types of milk. keep only one item per brand, exclude the non staple items purchased in the last 48 hours. Inject 10% percent high potential new SKUs for cold discovery. 
## Stage-4
We will do the logging of the process, run the feedback loop and monitor the Average order value, Average order units.   
1. The Dual-Storage Feature StoreOnline Store (Redis): Stores real-time, low-latency features (e.g., user:102:last_5_viewed_skus, store:55:oos_list). Query latency: $< 2\text{ ms}$.Offline Store (Databricks Delta Lake): Stores terabytes of historical interaction logs, user profiles, and order tables for weekly batch retraining.  
2. Feedback Loops & Training Cadence
Hourly / Daily: Candidate embeddings (Item Tower) and popularity scores are recomputed.

Weekly: The MMoE ranking model is retrained on the last 30–60 days of click-and-purchase event logs.

Continuous Monitoring: Tracking Data Drift (Population Stability Index - PSI) and Performance Decay (daily NDCG, AUC-ROC).   
2. Online A/B Testing Metrics (Live App Traffic)Primary Business KPI: Average Order Value (AOV) and Revenue Per User (ARPU).Funnel Engagement: Recommendation Widget CTR ($> 6\%$), Add-to-Cart Conversion Rate ($> 12\%$).Operational SLA: P99 Serving Latency $< 50\text{ ms}$.
